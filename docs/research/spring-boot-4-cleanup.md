# Spring Boot 4.1.1 cleanup review

**Review date:** 2026-09-14
**Scope:** `apps/api`, a Java 21 Spring MVC modular monolith.
**Sources:** Spring Boot 4.1.1, Spring Framework 7, Spring Security 7, Spring Data JPA 4.1.1, and Spring testing reference/API documentation only. The repository was reviewed at its current working-tree state; generated build output was inspected but not edited.

## Executive summary

The application is already substantially migrated: the build uses Boot 4.1.1 and Java 21, the security DSL is the current lambda-based `authorizeHttpRequests` form, tracked application code uses JSpecify rather than deprecated `org.springframework.lang` nullability annotations, and the Boot 4 test starters are already split by technology ([build.gradle.kts](/Users/chanakan5591/Developments/bgstore/apps/api/build.gradle.kts:9)).

The highest-value remaining cleanup is not a wholesale rewrite. It is to regenerate the OpenAPI sources, replace repeated test property plumbing with service connections, remove test-only nullable production constructors, add focused MVC/JPA slice coverage, and make native-query result mappings explicit. These are prioritized below. Items described as modernization are not claims that the current API is deprecated.

## Testing posture

The repository has a healthy base of plain Mockito unit tests and full `@SpringBootTest`/MockMvc tests. The latter are valuable for cross-module, PostgreSQL, Redis, security-session, and contract behavior, but they should remain the smaller integration layer. Spring MVC documents that direct controller calls do not verify request mappings, binding, conversion, validation, or advice; `MockMvc` does ([MockMvc overview](https://docs.spring.io/spring-framework/reference/testing/mockmvc/overview.html)).

For the next test cleanup pass:

- Add focused `@WebMvcTest` tests for controller mappings, validation, exception advice, and security. Boot 4.1.1’s MVC test module auto-configures MockMvc and security; use `@MockitoBean` or `@Import` for collaborators ([`@WebMvcTest` API](https://docs.spring.io/spring-boot/api/java/org/springframework/boot/webmvc/test/autoconfigure/WebMvcTest.html), [Boot testing](https://docs.spring.io/spring-boot/reference/testing/spring-boot-applications.html)).
- Add `@DataJpaTest` tests for repository queries, entity mappings, and native projection contracts. The slice focuses on JPA and rolls back transactions by default; retain Testcontainers where PostgreSQL behavior matters ([Boot test modules](https://docs.spring.io/spring-boot/reference/testing/test-modules.html)).
- Use `@MockitoBean`/`@MockitoSpyBean` for Spring-context bean overrides in new tests. They are the Spring Framework 7 test annotations for Mockito bean replacement/wrapping ([Spring Framework Mockito bean overrides](https://docs.spring.io/spring-framework/reference/7.0/testing/annotations/integration-spring/annotation-mockitobean.html)). The current source has no `@MockBean` or `@SpyBean` usage, so there is no direct migration to perform.

## Verified already current

- `SecurityConfiguration` uses `SecurityFilterChain`, lambda DSL, `authorizeHttpRequests`, and `csrf(csrf -> csrf.spa())`. No removed `WebSecurityConfigurerAdapter`, `authorizeRequests`, `antMatchers`, `MvcRequestMatcher`, or `AntPathRequestMatcher` usage was found. Security 7 removed the older request APIs in favor of the current forms ([Security 7 changes](https://docs.spring.io/spring-security/reference/7.0/whats-new.html)).
- Tracked `apps/api/src` contains no `org.springframework.lang.*` imports. JSpecify is already a compile-only dependency ([build.gradle.kts](/Users/chanakan5591/Developments/bgstore/apps/api/build.gradle.kts:63)). The remaining consistency improvement is to decide where to add package-level `@NullMarked` and whether the Java 21-compatible NullAway configuration should be tightened; do not enable a newer JDK-only mode without checking the toolchain.
- The application already uses Jackson 3 types in tracked source and has `spring.mvc.problemdetails.enabled=true`. That MVC property is current; it should not be removed merely because the code has a custom contract-shaped advice.
- `@Validated` remains on configuration properties only ([KeycloakProperties.java](/Users/chanakan5591/Developments/bgstore/apps/api/src/main/java/com/chanakanlabs/bgstore/security/KeycloakProperties.java:10)); no class-level controller validation proxy was found. `ApiExceptionHandler` already handles both `MethodArgumentNotValidException` and `HandlerMethodValidationException` ([ApiExceptionHandler.java](/Users/chanakan5591/Developments/bgstore/apps/api/src/main/java/com/chanakanlabs/bgstore/web/ApiExceptionHandler.java:68)), matching Spring MVC 6.1+/Framework 7 guidance ([MVC validation](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-validation.html)).

## Suggested order of work

1. Regenerate and compile OpenAPI sources; treat any remaining old Jackson/nullability/validation output as a generator compatibility issue.
2. Convert the four integration test container declarations to service connections, preserving Redis authentication and test isolation.
3. Remove nullable production constructors and add `@WebMvcTest`/`@DataJpaTest` coverage before changing controller or repository wiring.
4. Refactor native result mappings and decide whether method security should complement the existing domain policy.
5. Make the timestamp/auditing and package-level null-marking decisions deliberately, with migration tests where schema or runtime behavior changes.

## Implementation follow-up

The prioritized P1/P2 cleanup items identified above were applied after this research snapshot:

- OpenAPI generation now enables `useJspecify`, `useSpringBuiltInValidation`, `useSpringBoot4`, and `useJackson3`; regenerated output contains no Spring Framework nullability imports or controller-level `@Validated`.
- The four integration test classes use Boot `@ServiceConnection` for PostgreSQL and Redis, retaining the Redis password as an explicit test property.
- Required production collaborators are constructor-injected as non-null dependencies; test-only nullable constructors and fallback branches were removed.
- Native SQL repository methods use Spring Data JPA's dedicated `@NativeQuery` annotation.
- The API handles Spring MVC's built-in `HandlerMethodValidationException` and uses the current `UNPROCESSABLE_CONTENT` status name.
- API compilation with Java 21 and deprecation lint passes, and all non-container API unit/architecture tests pass. Full Testcontainers execution remains environment-dependent because no Docker daemon is available in this workspace.
